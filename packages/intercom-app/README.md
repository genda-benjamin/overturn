# Overturn for Intercom

QA for AI-drafted replies, inside the Intercom inbox. It records what the AI drafted, what the teammate actually sent and one line on why, and posts it to `POST /v1/capture`: the draft becomes a recorded run, the difference becomes a case, and the suite replays it against any model before the next prompt or model change. The drafting agent never has to be instrumented, and it does not matter who wrote the draft: Fin, another vendor's assistant, a homegrown drafter or a macro.

Canvas Kit app, conversation details surface. Same shape as [`packages/zendesk-app`](../zendesk-app), with one difference the platform forces and this app is honest about: **Intercom does not show an app the reply composer** (see [What Intercom lets an app see](#what-intercom-lets-an-app-see)).

## What the teammate sees

A small panel in the conversation details:

- **Draft inserted · 112 words** once a draft is known — either because the drafting agent recorded its run with the Overturn SDK (`externalId: "ic:<conversation id>"`), or because the teammate named the draft they can see in the composer.
- The run's origin, said out loud: "You said an assist wrote it: recorded as draft:ai", "You said you wrote it: recorded as draft:manual", or "Nobody said who wrote it: recorded as draft:unknown, never guessed."
- A **reason** picker with the installed pack's one-click codes (support by default: wrong answer, missing information, should have escalated…) and an optional note.
- **What you sent**, read from the conversation and editable, so the diff is against what really went out.
- On **Record the fix**: sent as drafted → an `approve` capture; changed → an `edit` capture with the reason as the case's title and the judge's rubric. A failed capture is reported in the panel and never blocks the send.

## What Intercom lets an app see

Canvas Kit Inbox requests carry `workspace_id`, `admin`, `conversation` and `contact` — and that is all ([docs](https://developers.intercom.com/docs/canvas-kit)). There is no composer field, no draft-created event and no send hook; requests only reach the app when a component is interacted with. So this app never invents a draft. It records one in exactly two ways:

1. **The assist told us.** The app asks the Overturn API for the latest run on `ic:<conversation id>` for this workflow (`GET /v1/runs?externalId=…&agent=…`). A drafting agent that recorded its run is found by itself, and the draft is its output — `draft:ai`, `recorded`.
2. **The teammate told us.** "The draft is in the composer" → paste the draft → say who wrote it ("Fin or another AI assist" / "I wrote it myself" / "Not sure — record it as unknown"). Their answer is the tag: `draft:ai`, `draft:manual`, or `draft:unknown`.

What Intercom does say about AI is used as evidence, never as a guess: each conversation part's author carries `is_ai_answer` ("this part's body was generated by the AI agent") and `from_ai_agent`, and the conversation carries `ai_agent_participated` ([reference](https://developers.intercom.com/docs/references/rest-api/api.intercom.io/conversations/retrieveconversation)). Those flags say nothing about the draft's text, so the panel repeats them as a hint and they only ever upgrade a teammate's "an assist wrote it" from `assist` to `fin`. A reply nobody told us about is `draft:unknown`; guessing an origin would be worse.

`require_reason` therefore holds the **capture**, not the send (Intercom gives an app nothing to hold): with it on, a changed reply with no reason code is not recorded, and the panel says so and asks for one click. Nothing is ever sent to the customer from here.

## Install

1. In Overturn, create a project API key (Settings → API keys).
2. Build and deploy the app:

   ```bash
   pnpm --filter @overturn-ai/intercom-app build     # dist/overturn-intercom-app.zip + dist/app
   OVERTURN_APP_URL=https://ov.example.run pnpm --filter @overturn-ai/intercom-app build
   ```

3. Run it where Intercom can reach it. A Cloudflare Worker (`dist/app/worker.mjs`) or the bundled Node server (`node dist/app/server.mjs`) both serve the same two routes.

4. In the Intercom Developer Hub, create the app (**Your Apps → New App**), then **Configure → Canvas Kit → For teammates → Within the Conversation Details** and paste:
   - **Initialize flow webhook URL**: `https://<your-host>/intercom/initialize`
   - **Submit flow webhook URL**: `https://<your-host>/intercom/submit`

5. Environment (worker secrets or `dist/app/config.json`, which is gitignored):

   | Key | Default | What it does |
   | --- | --- | --- |
   | `OVERTURN_API_KEY` / `overturn_api_key` | — | Project API key. Required; without it nothing is recorded. |
   | `INTERCOM_CLIENT_SECRET` | — | Verifies `X-Body-Signature` on every Canvas Kit request (HMAC-SHA256 over the raw body). Set it. |
   | `INTERCOM_ACCESS_TOKEN` / `intercom_token` | — | Optional. When a Canvas Kit payload arrives without conversation parts, the app reads the conversation back from `GET /conversations/{id}?display_as=plaintext` instead of guessing. |
   | `OVERTURN_BASE_URL` | `https://api.overturn.run` | Your Overturn API when self-hosting. |
   | `OVERTURN_AGENT` | `support-reply` | Workflow name; one regression suite per workflow. |
   | `OVERTURN_REASON_PACK` | `support` | `support` or `claims`: the one-click codes the teammate sees. |
   | `OVERTURN_REQUIRE_REASON` | `true` | Hold a changed capture until a reason code is picked. |
   | `OVERTURN_CAPTURE_NOTES` | `false` | Also record internal notes, not only replies. |
   | `OVERTURN_MIN_DRAFT_CHARS` | `80` | Shorter text is not a draft (a typed greeting is not a draft). |
   | `OVERTURN_SCOPE_TAG` | — | Only conversations carrying this Intercom tag are watched at all. |
   | `OVERTURN_MAX_CONTEXT_PARTS` | `40` | How many of the most recent messages ride along as context. |
   | `OVERTURN_DECISION_FIELDS` | — | Conversation custom attributes that *are* the decision, as `key:label`, e.g. `order_status:status`. Scored exactly; the prose is scored by the judge. |

   Canvas Kit forces these scopes on the app: Read conversations, Read and list users and companies, Read admins, Gather App data. The optional REST read uses the same token; note that a Canvas Kit app's API calls are checked against the access of the teammate who installed it.

  "source": "intercom",
  "externalId": "ic:21547896",
  "agent": "support-reply",
  "actor": "ray@carrier.com",

    { "role": "customer", "author": "dana@example.com", "content": "I was charged twice for order 8841.", "at": null },

## Replay what it captured

```bash
overturn cases list --agent support-reply
overturn replay --model openai/gpt-4.1-mini,together/deepseek-ai/DeepSeek-V4.1-Flash --agent support-reply
```

## Development

```bash
pnpm --filter @overturn-ai/intercom-app test       # payload builder, canvas, and the whole flow
pnpm --filter @overturn-ai/intercom-app typecheck
pnpm --filter @overturn-ai/intercom-app build
node dist/app/server.mjs                           # the two webhook routes on :8787
```

- `src/capture.ts` — settings, the thread, draft origins and the payload builder. Pure, no DOM.
- `src/canvas.ts` — Canvas Kit components and the screens, and what the app remembers on the canvas.
- `src/main.ts` — the handler both webhook routes call; the only file that talks to the network.
- `app/worker.mjs`, `app/server.mjs` — the two ways to serve it; signature verification lives here.
- `src/*.test.ts` — 58 tests, no live Intercom workspace needed.

Canvas Kit has no client state, so every click is a Submit request that re-renders the canvas: the draft, the picked chip and the screen ride in `stored_data`, and the picked reason is highlighted on the way back. The first canvas stays short and avoids a primary button, as the [Inbox design rules](https://developers.intercom.com/docs/canvas-kit/canvas-kit-inbox-best-practices) ask, and answering a recorded capture with `event: { "type": "completed" }` tells Intercom the app has done its job.

## Out of scope

Intercom reporting, per-teammate rates, and reading a conversation with no draft in it. Nothing here reads a conversation until a draft is known, and the scorecard stays a team number.
